# 值班提醒机器人：Server 2012 R2 免装运行库单文件打包（UCRT 依赖解决）

> 来源：2026-11-14 服务器部署排障。Server 2012 R2 上双击 exe 报「计算机中丢失 api-ms-win-crt-process-l1-1-0.dll」。本文记录根因、两条解法与已交付单文件版的约束，供后续重打包 / 重部署复用。

## 一、根因

- Server 2012 R2（2013 年系统）默认未装 **Universal C Runtime（UCRT）**，而 Python 3.12 打包的 exe 启动即依赖 `api-ms-win-crt-*.dll` + `ucrtbase.dll`。
- 这不是 exe 缺陷，是系统缺底层运行库；单文件版、目录版都会报同一类 `api-ms-win-crt-*` 缺失。
- 开发机（Win10/11）上 `api-ms-win-crt-process*.dll` 已合并进 `ucrtbase.dll`，System32 无独立文件可直接抽取，所以不能只靠 PyInstaller 自动收集。

## 二、两条解法（可并行，不冲突）

### 主路（干爹要的「免装」）：onefile 内嵌 UCRT

1. 源文件来源：根目录 `vc_redist.x64.exe`（微软官方自解压包）内 `cab` 装着整套 UCRT 真实文件（`api-ms-win-crt-process-l1-1-0.dll`、`ucrtbase.dll` 等全集）。
2. 用 `vc_redist.x64.exe /extract:目录`（或 7z）解出 cab 里的 `api-ms-win-crt-*.dll` 全集 + `ucrtbase.dll`（注意 downlevel 目录下的真实文件，非空壳）。
3. 打包：`--onefile --add-binary "提取目录\*.dll;."`，显式塞入 UCRT 全集 + `vcruntime140.dll`，别只靠 PyInstaller 自动收集（旧系统会漏这几个 API-set dll）。
4. 打包完静态核对这几组 dll 确在包内。

### 兜底（30 秒）：安装运行库

- 在服务器上装一次 `vc_redist.x64.exe` → 一路下一步 → **重启服务器**（重启才生效 dll）。
- 若仍报别的 `api-ms-win-crt-*` 缺失，是同一套库没装全，重装 vc_redist 即可。

## 三、已交付产物

- `服务器版\duty_reminder_server.exe`（30.9MB 单文件），已内嵌 `api-ms-win-crt-process-l1-1-0.dll`、`ucrtbase.dll` 等 UCRT 全集（downlevel 真实文件，静态验证可搜到）。

## 四、部署与约束（诚实提醒）

- 部署：把 `服务器版` 整个文件夹（exe + config.json + 排班表.xlsx）拷到服务器，双击 exe 试跑。
- ① 单文件运行会自解压到 `%TEMP%`，服务器若装实时杀软可能拦 `%TEMP%` 自解压 → 退回「装 vc_redist + 用目录版」。
- ② 若仍报缺别的 `api-ms-win-crt-*`，记录缺哪个，补塞该 dll 重打。
