# 值班提醒机器人：图形界面（GUI）架构决策（定版）

> 来源：2026-11-14 GUI 需求调研/架构决策阶段。承接最终版文档 `a82f102f-4942-4d2b-aac7-ccfcc16ddc21`（读导出 xlsx + 双击交互菜单）与 onedir 重打包 `a9cbb58a-f47d-4eaa-a5c9-13de2082ce6d`；排班规律仍引用 `8faa2a57-d3e2-4b3c-8517-a738e8a12e45`。编码开发阶段照本版执行，之后走 QA→安全→发布闸门。

## 一、总原则：UI 只做「壳层」，内核逻辑不动

- 界面仅把既有动作包成按钮/输入框；内核照旧读金山导出的 `排班表.xlsx` + 周末回溯带班领导，这段已 **21 项全绿，禁止改逻辑**。
- 回归红线：加 GUI 不得引入对 xlsx 读取、周末回溯、企业微信推送的回归。

## 二、命令行入口保留（勿断计划任务流程）

- `--install` / `--test` 命令行入口**保留**。
- GUI 里给「测试推送」「注册/卸载计划任务」按钮，图形版不得把计划任务注册流程弄断。
- 打包仍走 onedir（`a9cbb58a` 的根治方案），GUI 用 `--windowed` 打包（无黑窗/无控制台）。

## 三、三项 UI 交互拍板（干爹已确认默认值）

1. **双击行为**：双击 = 开图形窗口；带参数（计划任务 09:00 调它）= 静默推送、不弹窗。否则自动推送会弹窗。
2. **配置区**：可编辑 + 保存到 `config.json`（`webhook_url`、排班表路径都可在界面改）。
3. **窗口形态**：单窗口即可，不做系统托盘常驻。

## 四、日志口径：必须落盘 `run.log`

- 覆盖需求说明里「暂不落 run.log」那句：**日志界面回显 + 同步落盘 `run.log`，异常时写文件并弹窗提示**。
- 理由：GUI `--windowed` 打包后无控制台，崩溃/异常时界面回显可能根本没机会显示，不落盘连「去哪看」都没有。
- 配套要求（需求说明已全篇对齐）：webhook 脱敏、注册/卸载二次确认。
- 排障入口：出问题看 `run.log`。
