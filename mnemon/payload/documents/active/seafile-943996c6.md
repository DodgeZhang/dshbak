# 值班提醒机器人：数据源定稿（内网 Seafile 直链）与排班表结构变更重核

> 来源：2026-11-14 数据源收敛决策，覆盖「在线读取」方案 `4aed464d-1c2a-4e83-b0ff-06aec5ecc327` 中的「数据源待确认」三项（金山/腾讯/贴正确链接）。本决策终结三选一，并新增「排班表本身变更」这一关键风险，需架构/编码照此重核，勿用旧列序硬套。

## 一、数据源定稿：内网 Seafile 直链

- **定稿源**：内网 Seafile 直链（`10.165.84.174:8989`）——唯一实证能**免登录**拉到真实 `中心机房运维排班表.xlsx` 的源。
- **排除金山**：`kdocs.cn/l/choxOglCxDpc` 导出要登录态（403），不再是权威源。
- **排除腾讯**：链接实测空模板（`newEmptyDoc=1` + `templateId` + `isBlankPage:true`），无数据。
- 三选一终结，不再另选。

## 二、关键风险：排班表本身变了（不止「加在线读取」）

- 新表新增「带班领导」列 + 新领导，跟旧 5 人算法不同。
- 必须先把真实表结构钉出：日期 / 白班 / 带班领导 / 24H 各自列名 + 行数。
- **架构方案重核列映射**，重点防「白班」列抢掉「带班领导」列；编码开发按新映射实现，禁止拿旧列序/旧算法硬套。

## 三、实现口径：`fetch_seafile`

- 每次先 GET 分享页 → 解析最新直链 → 再下载；**JWT 会过期，绝不写死 token**。
- 失败回退链：缓存 → 本地。
- 数据源定为 `seafile`，复用 `online_url` 字段，**不新增配置项**。

## 四、安全收口（内网 HTTP）

- 内网 HTTP 单独开白名单：只许 `10.165.84.174:8989` 这一个 host。
- 输入框仍禁随意填 URL（不因此放开 SSRF 面）。
- `run.log` 不记带 JWT/签名的完整直链。
