# 值班提醒机器人（中心机房）实现与部署

> 来源：2026-11-14 完成的「中心机房值班提醒机器人」交付。排班规律关联文档 `8faa2a57-d3e2-4b3c-8517-a738e8a12e45`（《中心机房值班表排班规律》）。

## 交付物位置

项目目录：`C:\Users\zhang\.dsh\bot\workspace\值班提醒机器人\`

| 文件 | 说明 |
| --- | --- |
| `duty_reminder.py` | 主脚本（内置排班算法 + 企业微信推送 + Windows 计划任务） |
| `config.json` | 配置（webhook_url、白班/24H 名单等三项） |
| `使用说明.md` | 手把手部署步骤 |
| `dist\duty_reminder.exe` | PyInstaller 单文件（约 31MB，带控制台版本） |

## 三大功能

1. 每天 09:00 推送「今日值班 + 带班领导」，提醒填《每日巡检表》
2. 周末带班领导 = 当周白班（白班整周不变，算法天然满足）
3. 每月最后 5 天自动追加 4 项：消防检查 / 发电机启动测试 / 考勤统计 / 巡检表及出入登记汇总

## 排班依据（内置算法，非本地旧表）

内置 5 人模式（高国凯借调集团后）：**田晨、鲁强、蒋维、张德智、伊力潘江**，5 周一轮回。
交替律逐周验证通过：11/16 白班伊力潘江 → 11/23 田晨 → 11/30 张德智 → 12/7 蒋维 → 12/14 鲁强 → 12/21 回到伊力潘江。

## 部署两步

1. 把 `config.json` 里 `webhook_url` 换成真实企业微信机器人地址
2. 跑 `duty_reminder.exe --install`（或按 `使用说明.md` 注册计划任务）

## 排班数据源取舍（关键背景）

- 本地旧表 `D:\交投资料\相关文档\06-中心机房\中心机房运维排班表-新.xlsx` 是旧 6 人版（GBK 编码），已弃用不碰。
- 在线金山文档（kdocs.cn 分享页，真实文件 ID `380385228567`，文件名"云平台资源使用情况统计及故障统计.xlsx"）是「公路局机房」群组私有分享页；读 sheet 底层数据需用户本人 WPS/企业微信登录态（token），机器人侧无登录态，下载/导出接口均被拦（403）。
- 结论：工具排班走**内置 5 人算法**（规律即从该在线表逐格验证得出，确定性一致），更稳定、不依赖登录态；人事变动只需改 `config.json` 三项即可。

## 打包备忘

- 沙箱环境禁止创建临时目录，exe 在沙箱内跑会报 `Could not create temporary directory!`，属环境限制，真机双击/计划任务正常。
- PowerShell 会把 PyInstaller 的 stderr 当报错（`exit code 1`），但日志出现 `Build complete` 即为打包成功；控制台 GBK 乱码是 PowerShell 管道编码问题，非脚本 bug。
