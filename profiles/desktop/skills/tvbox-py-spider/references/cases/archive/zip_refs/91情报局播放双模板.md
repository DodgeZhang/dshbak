## 关键：站点有两种播放器模板

```
模板A（演员/番号视频）: /play/{pid}/x → 页面内 var playUrl = 'https://...m3u8'
    （aliplayer 直嵌，直接给 m3u8，正则: var playUrl\s*=\s*'([^']+)'）

模板B（首页/热门视频）: /play/{pid}/x → iframe player_a.html?id=https://{id}
    → /aa/{id} 接口（需 X-Requested-With: XMLHttpRequest + Referer: /static/html/player_a.html?id=https://{id}&rs=60）
    → 返回 m3u8（注意 &amp; → & 转义）
```

**两种都要支持**（先找 var playUrl，没有再走 iframe /aa/），否则"一部分能播一部分不能"。

## 坑（实战踩过）

1. **iframe id 两种格式**：纯数字（1005014535）或 16 位十六进制（fb6b0ccda0c67789ac68）→ 正则用 `[A-Za-z0-9]+` 不是 `\d+`
2. **m3u8 签名时效 ~60-100 秒**：detailContent 预解析的"直连"线路只对立即点播有效；备用线路用 pid 由 playerContent 点击时实时解析（永不过期）
3. **4 条 play-tab 线路 URL 完全相同**（同 pid，只是节点名"高清/刷新/电信/极速"不同）→ 去重保留即可
4. **详情页前部 img 全是广告** → 图片用 og:image / twitter:image
5. **分类 914(精品仓库)/959(特色资源) 站点本身 0 条**（共0条），非代码问题；主页导航含 杏吧资源 1274（109094 条）。**⚠️ 最终裁决（用户"还不如上一版"）**：改成 961 图片分类/补 1274 后用户要求回退——**保留用户 json 原始分类列表（914/959 留在原位）**，空分类向用户说明即可，不要自作主张换分类名
6. **/aa/ 接口**：直接 GET 会 403，必须带 X-Requested-With + Referer

## ★ 黄仓片源 t26/t30 → t33 替换（用户硬性要求）

```python
url = re.sub(r'//t26\.', '//t33.', url)
url = re.sub(r'//t30\.', '//t33.', url)
```

91情报局主要采集黄仓资源；片源若返回 t26/t30 域名必须替换为 t33，否则无法播放。分析任何相关源时必须提一嘴。
