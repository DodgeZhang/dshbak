# 智能加载：扫描根解析与文件浏览器归属实战

<!-- 演进: 2026-10-01 | 来源: webhome/Python/智能加载-v7.0.py | 类型: 扫描遍历/路径归属/UI 渲染 -->

适用于"管理型/文件浏览器型 py 源"：用户可配置扫描目录，脚本递归发现源文件并在 App 分类页里以"目录树 + 文件卡"形式展示。核心矛盾：**分类扫描（每类一个根）与用户期望（给任意目录都能像文件管理器一样浏览）之间的语义落差**。

## 需求模型

- 标准布局：扫描根是"分类容器"，下有 `Python(py)`、`js`、`csp`、`html` 四个类型子目录。
- 用户真实用法：根可能设成 webhome 容器、Python 目录本身、或 `TVBoxOSC` 这类任意结构目录，期望任意层级的 `.py/.js/.html/.json(csp)` 都能扫到并按真实目录树浏览，非源文件一概不显示。

## 平台/脚本事实

1. `os.walk(root)` 天然递归，只要 root 指向真实目录、扩展名过滤正确，任意层级文件都能命中——扫不到几乎总是"根解析错"，不是遍历问题。
2. 设置扫描路径时有 `_create_scan_base_tree` 自动建类型子目录的逻辑：**用户用旧版设置过路径后，目录里会残留 `py/js/csp/html` 空文件夹**，成为后续判断的污染源。
3. 每个源文件扫描时带 `scan_root`（命中的扫描根绝对路径）+ `relative_in_root`；文件浏览器完全靠这两个字段重建目录树，**不重新遍历磁盘**。
4. 回退模式下多个类型根可能解析到同一物理目录（如只有 html 子目录时，PY/JS/CSP 回退到父目录 webhome，HTML=webhome/html）。

## 三个连续 bug 与修复模式

### Bug1：非容器目录扫不到（Python/python 不存在）

- 现象：根=webhome 能扫到，根=webhome/Python 或 TVBoxOSC 扫不到。
- 根因：固定下钻 `<根>/py|python`、`<根>/js`... 子目录；根已是叶子目录时找到的是不存在的 `Python/python`。
- 修复：类型子目录**不存在则回退为根目录本身**（os.walk 递归 + 扩展名过滤兜底）。

### Bug2：回退后仍扫不到——空分类目录污染

- 现象：Bug1 修了，TVBoxOSC 根下散放单个文件仍扫不到。
- 根因：旧版设置路径时自动建的 `py/js/csp/html` 空文件夹恰好"存在"，"子目录存在就用子目录"的判断把根指向了空目录。
- 修复：采用子目录的条件从"存在"改为"**目录树下确实含文件**"（`_dir_contains_any_file`：os.walk 遇首个文件即返回，忽略隐藏目录，几乎零开销）。纯空/深层全空一律回退根自身。
- 教训：**任何"目录存在性"判断都要警惕历史自动创建残留**；判断"有没有东西"比"在不在"更可靠。

### Bug3：文件浏览 4 张重复卡片

- 现象：回退模式下文件浏览出现 `JS(PY)/JS(JS)/JS(JAR/CSP)/JS(HTML)` 四张卡片，各含同一批 72 个文件。
- 根因：浏览器根页按扫描根逐一生成卡片，4 个类型根路径相同 → 同一批 `scan_root` 相同的文件被渲染 4 次。
- 修复：根页按**物理路径归一去重分组**（`_browser_root_groups`）：同路径多类型合并成一张卡（卡片名不带类型后缀，就叫目录名）；独立类型目录保留 `目录名（类型）` 后缀。

### Bug4：点进 html 卡片空白（父回退根抢占子类型根）

- 现象：根页卡片显示 19 项，点进去"这里什么都没有"。
- 根因：判断"当前浏览目录属于哪个扫描根"时取**首个包含**它的根。回退父根 webhome 包含子目录 webhome/html，且遍历顺序在前 → 误选父根 → 用 `scan_root==webhome` 过滤 html 文件（实际 `scan_root==webhome/html`）→ 0 项。
- 修复：选**最深、最具体**的匹配根——路径最长者优先（精确相等自然胜出），不要"首个包含即 break"。

## 可复用规则

1. **扫描根解析**：`类型子目录含文件 → 用子目录；否则回退根自身`；容器/叶子/任意目录三态统一。
2. **路径存在性判断防残留**：优先判断"含内容"而非"存在"。
3. **UI 按物理路径归一**：同源数据多个逻辑分组指向同一路径时，展示层必须去重，不能按逻辑分组各渲一次。
4. **嵌套路径归属取最长前缀**：目录可能同时被父根、子根包含时，归属最具体的根（最长匹配），禁止"首个命中"。
5. **浏览器不重扫磁盘**：目录树由扫描期落库的 `scan_root + relative_in_root` 重建，因此扫描期的根归属必须准确，UI 层无法补救错误的 scan_root。
6. **文件夹只在含源文件时出现**：非源文件（txt 等）不入库，天然不渲染；只含非源文件的目录也不会出现，正好满足"像文件管理器但只显示支持类型"。

## 测试要点（桌面桩）

- 根解析依赖磁盘真实文件，桩测试必须**先落真实临时文件再算根**，不能只造内存源（"子目录含文件"判断读盘）。
- 必测四态：标准容器（4 个非空子目录）、叶子类型目录、任意目录+旧版空分类残留、混合布局（部分类型有子目录其余回退）。
- 浏览器必测：根页卡片去重数、卡片计数不重复、点进子类型根非空、点进回退父根不重复列入子树、深层子目录归属。
