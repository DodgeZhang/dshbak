# 404XAV 站点策略 v8.4
处理 404XAV 类多资源聚合站的动态域名、folder 分类、列表解析和 `play_data` 播放链路。
## 适用特征
- 发布页提供动态域名，目标域名前有随机数字前缀。
- 分类路由类似 `/list/{cid}/{subid}/{page}.html`。
- 页面出现 `web_api_types`、`web_grid_box`、`cell_box`、`v_thumb`、`v_title`。
- 详情页出现 `var play_data = "..."`，前端使用 pako `inflateRaw`。
## 路由模型
- 一级目录：`/list/{cid}/0/1.html`，解析 `web_api_types` 下的 `li > a`。
- 二级列表：`/list/{cid}/{subid}/{page}.html`。
- 搜索列表：`/search/{cid}/{key}/{page}.html`。
- 详情页：`/detail/{cid}/{hash}.html`。
- 无二级目录的分类直接解析视频列表，不伪造 folder。
## Folder规则
- 一级目录用稳定的 `dir_` 前缀 ID，并设置 `vod_tag: "folder"`。
- `categoryContent` 识别 `dir_` 后进入对应二级列表。
- folder 项不得写入伪造播放地址。
- 二级页必须保留真实分页字段；不能用固定 9999 或 999999。
## 列表字段
- 视频卡片优先解析 `cell_box`。
- 链接从 `v_thumb > a` 获取，图片读取 `data-original`、`data-src`、`src`。
- 标题从 `v_title` 获取，时长从 `v_time` 或页面文本回退。
- 过滤外部链接、分页导航、广告项和重复 ID。
- 所有相对 URL 统一补全并检查 `//`、`/`、完整 URL 三种形式。
## 播放链路
1. 详情页正则提取 `play_data`。
2. 使用 Base64 + raw deflate 解码 JSON。
3. 按 `video`、`url`、`file`、`play_url` 顺序读取媒体地址。
4. 以 `404XAV` 线路返回直链，点击时带站点 Referer。
5. 解码失败时再尝试页面直出、播放器变量、iframe 或 sniff。
- `parse:0` 只能用于确认后的 HTTP/HTTPS 媒体地址。
- m3u8 必须检查 `#EXTM3U`；详情页 URL 和播放器页 URL不能冒充直链。
## 动态域名
- 发布页解析出的候选域名必须探活并验证目标站结构。
- 请求失败、空页面或跳转壳出现时轮换域名。
- 域名变化不应影响分类、详情和播放路径。
- 具体历史域名、固定随机前缀和临时 CDN 不写入通用规则。
## 门禁
- 测试一级目录、二级列表、详情和搜索四条链路。
- 至少验证一个 folder 点击和一个真实视频播放。
- 抽测最终 m3u8 的 HTTP 响应和 `#EXTM3U`。
