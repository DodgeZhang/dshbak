# 18j_合并版：大佬动态分类体系 + t26/t30 替换（2026-08-24）

用户发来另一大佬写的 18J.TV.py（714 行），要求"合并 2 个版本优点"。本文件记录大佬版的核心架构增量与合并结论。

## 大佬版核心：动态分类体系（写 py 源时优先考虑）

**不是写死 MAIN_CATS，而是 init 时从站点动态抓取全部分类体系**，站点改版换分类自动适配：

| 数据 | 来源 URL | 提取 |
|------|---------|------|
| 主分类 + 子分类 | `{host}/label/sort/` | "视频类别"区块内 `<a href="/t/{id}/">名</a>`；子分类按主分类位置区间切分 |
| 类型筛选 | 同上 | 主分类名之间夹的子分类链接 |
| 排序 | `{host}/show/1/` | `filter-item` 类 `<a href="/show/1/by/{key}/">名</a>` |
| 地区 + 演员榜 | `{host}/modol/by/hits_day/` | `/modol/area/{值}/` 地区 + `filter-item` 榜单 |
| 黑料分类/排序 | `{host}/art/` + `/art/by/time/` | `arttype/{id}/` 分类 + `/art/by/{key}/` 排序 |
| 标签排序 | `{host}/tags/` | `/tags/?by={key}` |
| 导航入口（黑料/演员/标签） | `{host}/t/1/` 的 `<ol>` 导航 | href 首段映射 art/actor/tag |

执行：`init` 里按顺序调 `_fetch_main_cats()/_fetch_type_filters()/_fetch_sorts()/...` 填充 `self.classes`；全部 try/except，失败不影响域名解析。

## 大佬版其他优点

- **标签 folder 带数量**：`标签名(123)`（正则 `^([^(]+)\((\d+)\)$`）+ logo 占位图（`self.logo = host+'/xxx/manggo.png'`）
- **详情页信息齐全**：更新日期/人气热度/`status-red|green` 状态、相关标签、主演阵容——每类多级正则兜底（`dynamic-tags` → `tag-group` → 裸 div）
- **演员详情双保险**：先取 h1 名搜索过滤（`name in vod_name`）；无结果直接 `_parse_videos` 演员页作品（去重），不返回空
- **卡片 style**：列表项带 `"style": {"type": "rect", "ratio": 1.9}` / 演员 `oval` / 标签 `ratio: 3.0`（壳渲染更好看）
- **导航入口动态放 classes**：主分类后面跟 演员/标签/图文 三个 folder 入口

## 合并方案（templates/18j_合并版.py，验证全绿）

保留大佬动态体系全部，只加我版的唯一增量：
```python
@staticmethod
def _fix_play(play_url):
    if play_url:
        play_url = play_url.replace('//t26.', '//t33.').replace('//t30.', '//t33.')
    return play_url
```
在 detailContent 的播放 URL 提取和 playerContent 的 v: 重解析处都套 `self._fix_play(...)`（黄仓 t26/t30 → t33，否则这些片源无法播放）。

## 教训

- 用户发"另一大佬写的"参考源时，**先完整读懂其架构（动态 vs 写死分类）再决定合并什么**——不要只看功能对不对就照搬或忽略
- 我的旧版（写死 7 主分类 + 手维护子分类）在站点换分类时会失效；动态体系是 18j 这类站更稳的写法
- 合并时保留用户明确强调的规则（t26/t30→t33）不动，其余以大佬版为准
