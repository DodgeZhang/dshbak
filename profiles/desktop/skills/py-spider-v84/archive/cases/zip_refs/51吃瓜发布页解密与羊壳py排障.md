## 1. 发布页 key+data AES 解密机制（小男娘同款，密钥 0726001）

发布页（`wsuqyfdif.cc` / `51cgo11.com` / `fzchlelx.com`）HTML 里：
```html
<script>
window.appConfig = {
    key: "0726001",
    data: "NDI0YmUyMjEzMTAyNGFiZLtc3b50ds0b..."
}
</script>
```

**解密链（XBPQ 用户 json 方案）：**
```json
"发布页": "https://www.wsuqyfdif.cc/",
"key截取": "{{发布页}}[工具:源码#key:*\"截取\"]",
"key": "{{key截取}}[工具:SHA]",
"iv": "{{key}}[工具:1截取16]",
"域名解密": "{{发布页}}[工具:源码#// data:**data:\"截取\"#解aes-{{key}}-{{iv}}-AES/CBC/PKCS7Padding#线路一**\"value\":\"截取\"]",
"域名-c": "{{域名解密}}/"
```

**Python 实现（py 源）：**
```python
key_raw = re.search(r"key\s*:\s*\"([^\"]+)\"", html, re.I).group(1)   # "0726001"
data_b64 = re.search(r"data\s*:\s*\"([^\"]+)\"", html, re.I).group(1)
key_sha256_hex = hashlib.sha256(key_raw.encode()).hexdigest()          # 64位hex
aes_key = bytes.fromhex(key_sha256_hex)                                # 32字节
aes_iv = key_sha256_hex[:16].encode("utf-8")                           # 前16字符
cipher = AES.new(aes_key, AES.MODE_CBC, aes_iv)
text = unpad(cipher.decrypt(base64.b64decode(data_b64)), AES.block_size).decode(errors="ignore")
j = json.loads(text[text.find("{"):])
# JSON 字段: domain[0].value=线路一 / main / backup_domain.value
```

**解密后 JSON 关键字段：** `domain`（线路数组，`[0].value` 是线路一）、`main`（主域名）、`backup_domain.value`（备用域名）。

## 4. 羊壳 py 源"没数据"排障（本 session 核心教训）

用户羊壳导入 py 后**完全没数据、连分类页都不显示**。三个根因：

**① Crypto 库缺失 = 整个文件导入失败**：羊壳 py 环境常无 `Crypto` 包，顶层 `from Crypto.Cipher import AES` 直接 ImportError → 整个源加载失败。**必须降级**：
```python
try:
    from Crypto.Cipher import AES
    from Crypto.Util.Padding import unpad
    HAS_CRYPTO = True
except Exception:
    HAS_CRYPTO = False
# 解密函数里 if not HAS_CRYPTO: 返回原数据/None（列表播放照常，仅图片不解密）
```

**② self.classes 在域名解析之后设置 = 分类页空白**：`_resolve_domain()` 抛异常（网络/DNS）会中断 `init()`，`self.classes` 未初始化 → 分类不显示。**classes 必须最先设置 + 域名解析整体 try/except**：
```python
self.classes = [...]          # 先设分类
try:
    self._resolve_domain()
except Exception as e:
    self.host = "https://保底域名/"   # 永不抛异常
```

**③ e64/d64 基类缺失（用户截图 AttributeError 实证，最隐蔽的坑）**：羊壳的 `base.spider.Spider` **没有 `e64`/`d64` 工具方法**，`_img_proxy` 调 `self.e64()` 直接 `AttributeError: 'Spider' object has no attribute 'e64'` 崩整个源。**必须自实现**（用标准库 base64，不依赖壳提供）：
```python
def e64(self, s):
    try:
        return base64.b64encode(s.encode("utf-8")).decode("ascii")
    except Exception:
        return ""
def d64(self, s):
    try:
        return base64.b64decode(s).decode("utf-8")
    except Exception:
        return ""
```
**交付前用"基类只有 getProxyUrl、无 e64/d64"的最小环境测试**（模拟羊壳真实环境），不要 mock 工具方法——mock 会让测试通过但用户环境崩。

## 5. 5 秒超时保底（用户明确要求"优先自动获取，5秒无数据切保底固定域名"）

**⚠️ 最终版改用同步解析（用户纠正"我发给你那么多PY文件，你参考下啊"）**：用户全部 py 源（黄果重写版/红果升级版/小男娘/404标准版）**都没有 threading**——羊壳环境线程可能不可靠，且用户明确要求参考他的 py 文件风格。最终 51chigua.py 用**同步 + 短超时（4-5s）**逐级解析：

```
① 发布页解密 → 线路一 + cnmlgb 前缀（验证可用才用）
② 线路一原域名（cnmlgb 打不开时，dateModified 验证）
③ 落地页提取 + 二次跟随验证（循环最多3次）
④ 固定保底 twu78.cc（用户手机实测能开的域名）
```

- **保底域名必须用用户手机实测能开的**（用户说"备用域名可以打开"→ 保底 twu78.cc；不要用自己服务器能开但用户打不开的域名——`1yigt.fqnhogjc.com` 我服务器能开但用户环境未知）
- 5 秒保底诉求靠每步短超时实现（总超时≈10s 内必出结果），**不依赖线程**。**写 py 源默认同步风格，不要引入 threading**
- 配套：`_req()` 加**落地页跟随**（py 不执行 JS）：
```python
def _req(self, url, retry=True):

    if retry and "dateModified" not in text and "<article" not in text:
        m = re.search(r'href="(https://[^\"]+)"', text)
```

## 5b. 用户 json 优化版：cnmlgb 前缀域名方案（2026-08-19 最终稿）

用户两次修正后 json 的域名链（**py 按此实现，其他解析不动**）：
```json
"后缀解密": "{{发布页}}[工具:源码#// data:**data:\"截取\"#解aes-{{key}}-{{iv}}-AES/CBC/PKCS7Padding#线路一**\"value\":\"https:**.截取\"]",
"域名-c": "https://cnmlgb.{{后缀解密}}",
```
- `线路一**"value":"https:**.截取"` → 提取线路一 value 的**域名部分**（去掉 https://）
- `域名-c = https://cnmlgb.{域名}`（**固定前缀 cnmlgb.**，不带尾斜杠；URL 拼接处带 `/`）
- py 实现：`m = re.search(r'https?://([^/]+)', line)` → `cand = "https://cnmlgb." + m.group(1) + "/"`
- **验证再采用**：cnmlgb 前缀打不开（如服务器 SSL 握手失败）→ 降级线路一原域名（`dateModified` 验证）→ 落地页

## 5c. 二次落地页跟随验证（fzchlelx 陷阱）

落地页提取后**必须循环跟随验证**（最多 3 次）——`51cgo4.com → www.fzchlelx.com` 还是发布页（16150 字节）而非主站：
```python
for lp in self.landing_urls:

    for _ in range(3):
        rv = self.session.get(d, timeout=5, verify=False)

        if d2 and d2 != d: d = d2

```

## 6. 图片 AES 两种形态（json 图片不显示的根因）

`loadBannerDirect('https://pic.xustgq.cn/upload_01/xiao/...jpg')` 里是**明文 URL**，但 **URL 指向的文件内容才是 AES-CBC 加密的**（下载后文件头 `>\xaap\x8e` 非 JPEG；解密后 `\xff\xd8\xff` 是 JPEG）。

- **XBPQ json 做不到**：`[工具:源码转b64#解密aes-...]` 是对 URL 文本解密（错），工具链无法"下载再解密" → json 图片必挂
- **py 正确做法**：localProxy 里 `requests.get(url).content` → AES 解密（key=`f5d965df75336270`/iv=`97b60394abc2fbe1`）→ 返回 JPEG
- **判定方法**：图片能下载但播放器不显示 → 看字节头（`\xff\xd8`=JPEG 正常 / 其他=加密）→ 再区分"页面密文文本"（json 可解）vs"下载字节流加密"（只能 py）

## 10. 分类列全 flat 写法（红果风格，用户要求"子分类直接显示"）

用户反馈"子分类都没写，比如娱乐天地下面有很多分类，你只写了一个"——**子分类要作为独立分类直接列出**（flat class 列表），不能只藏在 filters 里：
- 站点导航栏本身就有全部子分类链接（`/category/whhl/` 网红黑料、`/category/ysyl/` 看片娱乐…共 20+ 个，实测全部 200 + 数据）
- classes 直接列 26 个（主分类 + 全部子分类），type_id 就是分类 id
- filters 保留（红果 hongguo2 风格）：`filter_dict = {type_id: groups}`，每组 `[{"key":"类型","name":"类型","value":[{"v":"","n":"全部"},{"v":"ysyl","n":"看片娱乐"},...]}]`
- categoryContent 筛选合并（hongguo2 写法）：`for d in [filter, ext]: if isinstance(d, dict): for k,v in d.items(): if v and k not in ("page","pg"): params[k]=v`；`params.get("类型")` 直接当分类 id 切页
